**核心结论**：本地文件夹的名称和 GitHub 远程仓库的名称是**互相独立**的。更改名称时**不需要**将两者同时修改。

以下是三种常见重命名场景的具体操作汇总：

| **场景**  | **修改目标**     | **核心原理**                               | **操作步骤**                                                                                                                                                  | **终端命令**                            |
| ------- | ------------ | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| **情况一** | **仅修改本地项目**  | Git 识别项目依赖的是隐藏的 `.git` 目录，不受外部文件夹名称影响。 | 1. 关闭占用该项目的编辑器。<br><br>  <br><br>2. 在资源管理器中直接将文件夹重命名。<br><br>  <br><br>3. 重新在编辑器中打开即可正常使用 Git。                                                            | **无需任何命令**                          |
| **情况二** | **仅修改云端仓库**  | 修改 GitHub 仓库名会导致远程链接变更，必须在本地更新该链接。     | 1. 进入 GitHub 仓库主页，点击 `Settings` -> `General` -> `Repository name` 进行重命名并保存。<br><br>  <br><br>2. 复制新仓库的 HTTPS/SSH 地址。<br><br>  <br><br>3. 在本地项目终端执行地址更新命令。 | `git remote set-url origin <新仓库地址>` |
| **情况三** | **本地与云端均修改** | 结合前两种方式，保证本地与云端命名统一。                   | 1. 资源管理器中重命名本地文件夹。<br><br>  <br><br>2. GitHub 中重命名远程仓库。<br><br>  <br><br>3. 在本地终端重新绑定新仓库地址。                                                               | `git remote set-url origin <新仓库地址>` |
